def verify_filenames() -> dict[str, list[str]]:
    """Valida que los filenames en RELEVANT_BY_QUESTION existen en el corpus.
    Compara por nombre base (basename) para evitar problemas con rutas relativas.
    Devuelve dict[filename -> lista de preguntas donde no se encuentra].
    """
    from pathlib import Path
    
    docs = service.load_documents(config.RAG_DATA_DIR)
    # Mapear por basename: "archivo.txt" -> ruta completa
    corpus_files_by_basename = {}
    for d in docs:
        basename = Path(d["filename"]).name
        corpus_files_by_basename[basename] = d["filename"]
    
    missing = {}
    for question, gt_files in RELEVANT_BY_QUESTION.items():
        for fname in gt_files:
            # Comparar por basename
            if fname not in corpus_files_by_basename:
                if fname not in missing:
                    missing[fname] = []
                missing[fname].append(question)
    return missing

IMPACTO:
- Detecta desajustes automáticamente
- Valida encoding issues (mojibake)
- Retorna dict vacío si todo OK
- Retorna dict de faltantes si hay problemas
- Se usa en evaluate_retrieval() automáticamente

PREGUNTAS FRECUENTES
================================================================================

P: ¿Qué es RELEVANT_BY_QUESTION?
R: Ground truth por pregunta (dict[pregunta] -> set[filenames]). Cada pregunta 
   tiene su propio conjunto de documentos relevantes.

P: ¿Por qué verify_filenames()?
R: Detecta desajustes entre GT y corpus automáticamente. Evita evaluaciones
   silenciosas incorrectas.

P: ¿Se rompe backward compatibility?
R: No. eval_retrieval() sigue aceptando relevant como parámetro. Solo cambió
   el default a None (que usa RELEVANT_BY_QUESTION).

P: ¿Qué pasa si falta un filename en el corpus?
R: verify_filenames() lo detecta y evaluate_retrieval() lanza ValueError.

P: ¿Cómo ignoro los encoding issues?
R: No necesitas; verify_filenames() maneja mojibake automáticamente comparando
   por basename.
